# Doctree data

Pre-built multimodal document trees — the offline artefact described in §3.2 of
the paper. One directory per document:

```
data/doctree/mmlongbench/
└── <doc_id>/
    └── tree_index.json
```

> Navigation reads exactly those fields, so the pipeline will not run on this

> is expected).

## Schema

```jsonc
{
  "doc_id": "2307.09288v2",
  "source_dir": "",              // cleared on export; see scripts/export_doctree.py
  "num_pages": 77,
  "root_summary": "",            // document-level summary
  "sections": [
    {
      "id": "sec_preface",
      "title": "Preface",
      "start_page": 0,           // 0-indexed, inclusive
      "end_page": 1,             // 0-indexed, inclusive
      "summary": "",             // section index card s_i
      "pages": [
        {
          "page_idx": 0,
          "image_path": "images/page_1.png",   // relative to the image root
          "ocr_text": "LLAMA 2: Open Foundation...",
          "summary": "",                        // page summary p_j
          "elements": [
            {
              "id": "elem_0_0",
              "type": "text",                   // MinerU layout category
              "page_idx": 0,
              "bbox": [112, 237, 274, 250],     // [x0, y0, x1, y1] on the source page
              "text": "FOR RELEASE MAY 3, 2018",
              "path": "",                       // cropped region, when materialised
              "caption": ""                     // figure/table caption
            }
          ]
        }
      ]
    }
  ]
}
```

`type` takes values in `{table, figure, chart, image, diagram, graph, text,
page_number, header, footer, list, code, equation, aside_text, page_footnote,
ref_text}`. The paper's element node `E_k = (type_k, bbox_k, t_k, c_k, I_k^crop)`
maps onto `type` / `bbox` / `text` / `caption` / `path`.

## Page images

Page images are **not** redistributed — MMLongBench-Doc source PDFs carry their
own licences. `image_path` is relative, so point it at your own MinerU output:

```
<your-mineru-root>/<doc_id>/images/page_1.png
```

Get the source documents from
[MMLongBench-Doc](https://github.com/mayubo2333/MMLongBench-Doc), run
[MinerU 2.5](https://github.com/opendatalab/MinerU) over them, and resolve
`image_path` against `<your-mineru-root>/<doc_id>/`.

## Regenerating

Rebuild trees from MinerU output, then populate summaries with a VLM:

```bash
python scripts/convert_mineru_data.py --all       # MinerU -> tree_index.json
python scripts/generate_summaries.py --all \      # page + section summaries
    --model Qwen/Qwen3-VL-30B-A3B \
    --base-url http://YOUR_VLM_SERVER:8000/v1
```

Both scripts arrive with the code migration; the prompts they use are already
in [`prompts/`](../prompts/README.md).

To re-export trees from a working directory into this release layout (rewriting
absolute paths to relative ones):

```bash
python scripts/export_doctree.py \
    --src /path/to/working/data/processed \
    --dst data/doctree/mmlongbench
```
